# 技能卡：Educoder 实训逐关填答与评测

## 适用场景

- 用户有一份本地答案目录（每关一个 `.c`/`.h` 文件，文件名带关卡序号）。
- 目标：把这些答案覆盖到平台对应关卡，并逐关提交评测，直到全部通过。
- 不适用：需要绕过平台限制、伪造成绩、代考等场景。

## 前置条件

1. 浏览器已登录目标课程；**优先使用独立 profile 的 agent 浏览器**，避免与用户日常窗口争抢焦点。
2. 已拿到“关卡 ↔ 文件 ↔ 平台路径”的映射（本项目 `docs/INDEX.zh-CN.md`）。
3. 清楚平台频率限制（本项目按 **两次评测间隔 ≥30 秒** 执行）。

## 能力清单（工具 → 用途）

| 工具 | 用途 | 注意 |
| --- | --- | --- |
| `list_windows(browserLane=true)` | 枚举标签页、判断登录态 | 返回 `browsers` 为空说明没有 CDP 通道，需要新开 agent 标签页 |
| `set_value(elementId="new-tab", value=URL)` | 后台开新标签页 | 隔离 profile，不带用户 Cookie |
| `snapshot(browserTab=...)` | 读页面结构 + 截图 + 元素 id | 元素 id 形如 `t1a2b:57` |
| `find(query, browserTab=...)` | 按文本找元素（推荐） | 比坐标稳；返回小，适合反复调用 |
| `click(elementId=...)` | 页面内点击 | 不会移动桌面光标；被遮罩挡住会返回 `BROWSER_ELEMENT_COVERED` |
| `keypress(browserTab=..., keys=["F5"])` | 页面级按键 | 用来清掉通关弹窗 |
| `wait(ms)` | 等待 | 评测 15~20s；评测间隔 30s |

## 标准流程

1. **定位作业**：`find("实验N")` 或直接打开作业详情页；确认关卡总数与本地文件数一致。
2. **逐关进入**：从第 1 关开始，用页面底部“下一关”推进；需要后退时用“上一关”（先 `F5` 清弹窗）。
3. **校验已填内容**：可选——`snapshot` 读出 `textbox` 的 `value`，与本地文件比对（去掉行尾空白与 BOM 后应完全相等）。
4. **评测**：`find("run 评测")` → `click`；`wait(15000~20000)`。
5. **判定**：`find("全部通过")`
   - 命中 → 通过，点“下一关”/“完成”。
   - 未命中 → **立即停止**，输出：关卡名、期望输出、实际输出、命中率。
6. **限速**：每次评测之间 `wait(30000)`，期间不发起任何请求。

## 停止条件（必须遵守）

- 任一关评测失败 → 停止整个循环，汇报失败点。
- 页面出现“服务启动中…/努力请求数据中…”超过 30 秒 → 停止并汇报（多半是会话过期或平台限流）。
- 登录态丢失（`find("登录 / 注册")` 命中）→ 停止，请用户重新登录。
- 连续两次 `click` 返回 `BROWSER_ELEMENT_COVERED` → 说明有遮罩弹窗，先关弹窗再继续。

## 常见坑

1. **通关弹窗挡路**：通过后必有“恭喜您通过本关”遮罩。点弹窗按钮，或 `F5` 后点页面按钮。
2. **多文件题**：编辑器左上“代码文件”下拉对合成点击常常无响应。此时不要硬试，改为手工粘贴剩余文件，再点评测。
3. **直接访问关卡 URL 可能空白**：优先从“作业详情 → 继续挑战”或页面内“上一关/下一关”进入。
4. **`.h` 题不要整份编译**：只替换头文件内容，平台主程序在别处。
5. **“填空/改错”题**：整份覆盖可能破坏平台包在外面的代码，只替换 `Begin…End` 之间的函数体。
6. **不要用桌面级鼠标键盘**：会抢前台、动用户光标；有 CDP 就用 CDP。
7. **一次只发一个工具调用**：评测有节流，批量并发只会互相触发限流。

