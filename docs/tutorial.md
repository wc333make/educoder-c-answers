# 使用教程：从零把答案填进头歌，并批量评测

本文分三部分：**A. 纯手工**（10 分钟学会）、**B. 半自动**（Agent 帮你切关、你只负责粘贴）、**C. 全自动后台提交**（CDP，不抢鼠标）。选一种即可。

---

## 0. 前置

- 一份答案目录（本仓库 `answers/`）。
- 一个能打开头歌课程页的浏览器，已登录。
- 想走 C 方案的话，需要一个能操作浏览器的 Agent 环境（本文以 DeepSeek Harness 的 `windows_computer_use` 工具集为例）。

**重要原则**：能不用“桌面级鼠标键盘”就不用。桌面级操作会抢前台、动你的光标，一旦你正在用电脑就会互相打架。浏览器通道（CDP）在后台跑，才是正确姿势。

---

## A. 纯手工流程

1. 课程页 → 实训作业 → 点某作业的“开始学习”。
2. 进入第 1 关，左边是题目，右边是 Monaco 编辑器。
3. 在 `docs/INDEX.zh-CN.md` 里 `Ctrl+F` 搜题名，找到文件名与“平台路径”。
4. 编辑器内 `Ctrl+A` → `Delete` → 粘贴整份文件 → 等右下角出现“已保存”。
5. 点 **评测**（不是“自测运行”）。
6. 看“测试结果”：`n/n 全部通过` 即通过；出现红叉时展开测试集，对照“输入/输出”改代码。
7. 通过后弹“恭喜您通过本关” → 点 **下一关**（最后一关是 **完成**）。
8. 下一关重复 3~7。

多文件题：编辑器左上角 **代码文件** 下拉里有多个文件（如 `src/step5/file1.c`、`file2.c`、`file.h`），逐一点开、逐一覆盖，最后再评测。

## B. 半自动（推荐给大多数同学）

让 Agent 负责“导航 + 评测 + 记录”，粘贴由你完成（或者反过来）。

Agent 侧典型指令：

> 打开课程页，找到“实验五 数组”，从第 1 关开始；我粘完一关你点评测，通过就点下一关，失败就停下来告诉我。每两次评测之间等 30 秒。

Agent 会做这些事：

| 步骤 | 工具 | 说明 |
| --- | --- | --- |
| 找到标签页 | `list_windows(browserLane=true)` | 拿到 tab id、是否已登录 |
| 读页面 | `snapshot(browserTab=...)` / `find(query)` | 拿到元素 id（如 `t1a2b:57`）与标题 |
| 进入关卡 | `click(elementId=...)` | 点“开始学习 / 下一关 / 上一关” |
| 判断结果 | `find(query="全部通过")` | 命中即通过，未命中即失败 |
| 等待 | `wait(ms)` | 评测一般 5~20 秒；两次评测间隔 ≥30 秒 |

你只需要在 Agent 说“第 N 关已就绪”时，把对应文件粘贴进去。

## C. 全自动后台提交（CDP）

### C.1 用独立浏览器 profile

不要用你日常那个已登录的浏览器去接自动化：它通常没有开调试端口（CDP），Agent 只能退化成“桌面点击”，会抢你的鼠标。

正确做法是让 Agent 开一个**隔离的 agent 浏览器**（独立 profile、独立 Cookie），你在那个窗口里登录一次：

```
set_value(elementId="new-tab", value="https://www.educoder.net/classrooms/<课程>/shixun_homework")
```

然后在弹出的独立窗口里完成登录。之后所有操作都在后台完成，**不移动你的光标、不切换你的前台窗口**。

### C.2 逐关循环（Agent 伪代码）

```
for 每一关 in 当前作业:
    等待页面出现 "run 评测" 按钮（find "run 评测"）
    click(评测)
    wait 15~20s
    if find("全部通过") 命中:
        收下结果，(非末关) click("下一关")
    else:
        记录失败关卡 + 展开的测试集差异
        break            # 失败即停，交给人判断
    wait 30s             # 平台频率限制，期间不要发任何请求
```

### C.3 通关弹窗的正确处理

通过后会出现“恭喜您通过本关”的遮罩弹窗，它会**挡住页面内的“上一关/下一关”**，此时点页面元素会报 `BROWSER_ELEMENT_COVERED`。三种处理：

1. 点弹窗里的 **下一关**（前进）；
2. 点弹窗里的 **完成**（末关），弹窗关闭；
3. 需要后退时：先按 `F5` 刷新页面（弹窗消失），再点页面底部的 **上一关**。

### C.4 失败即停的意义

失败通常意味着：答案与平台测试用例不匹配、题面与公开答案有出入、或该关需要多文件而只粘了一个。**继续跑只会浪费评测次数与时间**，所以停下来，人看一眼测试集的输入输出最快。

## 常见问题

**Q：粘进去编译不过？**
A：多半是把 `.h` 当整份程序粘，或漏了 `#include`。`.h` 题只提供函数体，平台的主程序在另一个文件里。

**Q：明明代码对，评测却不通过？**
A：① 输出格式（空格、换行、小数位）不符；② 多文件题只改了一个文件；③ 该关是“填空/改错”题，平台会在你的代码外面再包一层，整份覆盖反而破坏结构——此时应只替换函数体。

**Q：能一次把所有作业都跑完吗？**
A：可以，但建议**每个作业一个标签页**、以作业为单位收尾，避免页面状态过期后跳到别的作业。

**Q：会不会被判定作弊？**
A：自动化只是省去重复劳动。是否允许提交参考答案由课程规定决定，请自行确认后再操作。

**Q：需要给平台留多少间隔？**
A：实测 **≥30 秒**比较稳妥；期间不要连续触发评测，也不要并发开多个关卡同时评测。
