# 这次实际用到的 DSH 能力清单

把一次“18 个作业、121 道题、上百次浏览器操作”的任务拆开看，真正起作用的只有几项能力。下面按“解决问题 → 用了什么”记录，方便你在自己的 DSH 环境里复刻。

## 1. 浏览器通道（CDP）——后台操作页面

- `list_windows` 的 `browserLane` 段给出可用标签页；`browsers` 为空说明没有调试通道。
- `set_value(elementId="new-tab", value=URL)` 在**隔离 profile** 里开新标签页：不带你的登录 Cookie，也不抢焦点。
- `snapshot` / `find` 拿元素 id（`t1a2b:57`），`click` / `keypress` 只发给页面，**不移动鼠标、不切换前台窗口**。

关键经验：优先找“带 `run`/`link` 角色的按钮 + 文本查询”，比记坐标稳得多；坐标会随缩放、窗口大小、页面滚动漂移。

## 2. 桌面级兜底（UIA + 截图）——只在没有 CDP 时用

- `find` / `invoke` / `screenshot` 能操作没有调试端口的普通窗口。
- 代价是**必然占用前台**：会抢走你的鼠标和键盘。本次就因为桌面输入与用户操作打架被中断过两次。
- 结论：**有 CDP 就别用桌面**；必须用时，先问用户“现在可以占用桌面吗”。

## 3. 剪贴板桥接——把长代码塞进 Monaco

- `pwsh` 里 `Set-Clipboard -Value ([IO.File]::ReadAllText(path))` + 页面内 `Ctrl+A` / `Ctrl+V`。
- 好处：不经过模型输出，长文件（几千字符）也不会被截断或改写。
- 校验：`Ctrl+A` → `Ctrl+C` → `Get-Clipboard` 与源文件比对（去 BOM、去行尾空白后应完全相等）。

## 4. 上下文压缩——长任务的续航

- 上百次工具调用后上下文会爆。用 `compress` 把“已消费”的区间折叠成自包含摘要（保留：目标、约束、坐标/URL、失败原因、待办）。
- 每次折叠都记下“当前状态：第几关、哪些已通过、下一步做什么”，恢复时不用重读历史。

## 5. 定时/批处理节奏

- 任务要求“两次评测间隔 30 秒”，用 `wait(30000)` 实现静默等待，期间不发任何请求。
- 失败即停比“继续跑完”更有价值：省评测次数，也省你的时间。

## 6. 不该做的事（教训）

- 不要用桌面点击去“代替”页面内点击——除非确实没有调试通道。
- 不要并发开多个关卡同时点评测——平台会限流。
- 不要在页面还在“努力请求数据中…”时点击——事件会丢。
- 不要把 `.h` 题当整份程序提交；不要对“填空/改错”题整份覆盖。
